# WRotate — Model (reference) page, as built · 2026-08-29

Share this with Claude Design as the ground truth of what the app renders today.
Built from the "Reference Page 2a" handoff; deviations from that design are
listed at the end. Everything is behind the `watch_db` dev flag until launch.

## Where it lives / how you reach it
- In-app page `#page-model` (390px column, max 480px). Entry points: Feed → **Watches** (Explore grid, search, brand chips) → card; Collection → any watch → "Also owned by" row; any watch tapped in the Feed → preview sheet → "See this model".
- A public, logged-out twin exists at `wrotate.com/w/?m=<slug>` (older layout, facts as teasers only).

## Data the page has (one `model_stats` call + the model row + facts)
Model row: brand, name, slug, curated `specs` {type, size, water_resistance, movement, materials}, hero_image (+credit), LLM enrichment: `description` (1–2 sentences), `history` (3–5 sentences), `refs_by_era[]` {reference, years, note}, `calibers_by_era[]` {caliber, years}.
Stats (all with sample sizes, no floors): owners, public_owners, wishlisted, wishlisted_by_me, top_ref, wears {w90, wearers90, all_time}, wear_strip[15] (6-day buckets), wear_weeks[12], accuracy {n_sessions, n_measurers, med_rate, med_abs_rate, med_amp, hist[13] over −25…+14 s/d}, value {median_now, n_contributors, series[{ym, median, n}]}, cost_per_wear {median, n_owners, wears}, wear_share {index, share%, fair%, n_owners, wears, pct_rank, n_models, bench {brand, type, type_label, all}, retention[{bucket, share, n}]}, era[6] (60s…10s+), tenure {years, n}, specs_agg {caliber, case_diameter, case_material, movement_type, water_resistance, year_range → {v, n}}, photos[] (public owners' photos), related[] (same brand, by owners), brand_models, mine[] (viewer's own watches on this model, with last measured rate).
Facts: the model's fun-fact pool (`watch_facts`), generated by the app; **many models have only 1–2 facts today**, common ones more. Not member-submitted.

## Vertical order (single scroll)
1. **Hero** 240px — hero photo (Wikimedia/admin upload) else first public owner photo; left-to-right dark scrim; top row `‹ Back` (page back, not brand) / `Share` (public /w/ link); bottom-left eyebrow `BRAND · REF. <top ref>`, title 27px, caption `type · size · WR · movement · era`; tiny photo credit bottom-right when the hero is a Commons image.
2. **Stat grid 2×2**, hairline-separated: Median rate (+13-bin mini histogram, "N measurements · N members") · Median value (+area sparkline, "▲ x% since Mon · N valuations") · Wears / 90 days (+15-cell strip, "by N of M owners") · Cost per wear (+progress bar, "N owners tracking"). Fallback cells when a figure is absent: Owners, Wishlisted, Wears all-time.
3. **Fun-fact band** (gold-dim) — "FUN FACT · i of N", 2-line clamp, rotates daily; tap → Lore tab and scrolls the tab bar to the top.
4. **Tabs** Data · Specs · Lore · Owners (`role=tablist`; Data hidden when no member data; Lore hidden when no facts).
5. **Panels** (min-height 420px):
   - **Data**: Wear share card (index×, share vs fair explainer, bars: This model / All <brand> / <type> watches / Every model, "Does it last" retention bars when ≥2 buckets, footer `Top X%` of N models · wears from N collections) · Rate distribution (13 bars, axis −25 / median / +14, cards Amplitude · Drift · Members) · Wear pattern (12 weekly bars + note).
   - **Specs**: Member-verified grid (label / value / "N watches") · Reference spec (curated) · References by era · Calibers by era.
   - **Lore**: "N facts" + Exclusive badge · enrichment history paragraph · one card per fact.
   - **Owners**: big count + era span · Ownership by era (6 bars) · cards Median tenure / Wishlisted / Private collections / Wears logged · note "Individual owners are never listed here…".
6. **More from <brand>** — top 4 by owners + `All N <brand> models ›` (opens Explore filtered to the brand).
7. **Request an edit** pill → in-app feedback form, prefilled with model + tab.
8. **Action bar** (sticky bottom): `Add to collection` (→ prefilled add-watch modal) or `Open your <model>` when owned; `♡ Add to wishlist` or `♥ On your wishlist`.

## Deviations from the 2a design (all agreed)
- Owners are aggregate-only (no identities) — as designed; the earlier "names-gated owner list" was dropped.
- `‹ Rolex` → `‹ Back`; the brand route lives in "All N Rolex models".
- No Beat error card (not captured yet) → replaced by Members; no Still owned / Serviced cards (no data; "sold" is on the backlog) → Wishlisted / Wears logged.
- No "N sourced by members" / "Add a fact" — facts are app-generated only.
- No "Suggest a correction" (Request an edit covers it).
- No member floors — figures show from n=1 with the sample size beside them.
- Tabs are in-app state, not in the URL.

## Open design question for the next round
The Lore/facts content is the part members most enjoyed in the old flow (tapping a watch on a post opened a sheet with the fact right there). On the new page it sits behind the band + a tab. Explore bringing lore above the fold: e.g. the band showing a full fact (no clamp) with swipe/next, a lore card between the hero and the stat grid, or the hero caption carrying the fact. Constraint: fact pools are thin for most models (1–2 facts), rich only for popular ones.
