# Languages

English is written in the code and is also the dictionary key. A non-English user
loads one extra file; an English user loads nothing and runs none of this.

## How it works
- **Loader** (`index.html` head): reads `wr_lang` from localStorage (or `?lang=es`,
  which stores it). Only for a supported language does it load `/i18n/<lang>.js`,
  blocking, so the dictionary exists before the boot script draws anything.
- **`tx('English', vars)`** (not `t`: that name is a local variable all over the page): returns the translation, or the English when there is no
  dictionary or no entry. `{name}` placeholders are filled from `vars`.
- **`i18nWalk()`**: at boot, translates the static markup in place (text, `placeholder`,
  `aria-label`, `title`, `alt`). No markup changes are needed for a static label.
  Skipped: `#auth-screen` (the sign-in screen is not to be modified), the admin portal,
  the What's New archive, and anything under `data-i18n-skip`.
- **`toast(msg)`** translates its message itself.
- **Live translator**: a MutationObserver runs the same walker over everything the script
  draws later (cards, lists, modals). Whole-string matches only, so captions and watch
  names are left alone. `i18nLookup()` also handles numbers ("3 wears" is looked up as
  "{0} wears"), dot-separated labels ("2h ago · work") and sort arrows ("Paid ↕").
- **Dates** use `I18N_LOCALE` (the chosen language; `en-US` for English).
- **Choosing**: Profile -> Language (`I18N_LANGS`, `setLanguage()`), stored in
  localStorage `wr_lang` and mirrored to `profiles.language`. English is the default; nothing is auto-detected yet.
- **Finding gaps**: set `window.__i18nMiss = new Set()` before boot and every label that
  found no entry is collected there. Add ones the extractor cannot see (lower-case list
  values, text built by string concatenation) to `i18n/extra.keys.json`.

## Files
| File | What | Edited by |
|---|---|---|
| `i18n/en.keys.json` | every string the page can translate | `node scripts/i18n.mjs extract` |
| `i18n/<lang>.json` | English -> translation | hand / translator |
| `i18n/<lang>.js` | what the browser loads | `node scripts/i18n.mjs build` |

## After changing any user-visible text
1. `node scripts/i18n.mjs extract` (needs Playwright's chromium)
2. `node scripts/i18n.mjs status --missing`, then add the new strings to each `i18n/<lang>.json`
3. `node scripts/i18n.mjs build` (also stamps the `?v=` hash; a unit test fails if stale)

## Writing new code
- Static label in markup, or a whole label inside a template: nothing to do.
- Text set from JS: `el.textContent = tx('Saved')`.
- With a value: `tx('{n} watches', { n })`, never `n + ' watches'`.
- Do not translate user content, brand/model names, admin screens or email HTML.

## Adding a language
Add `i18n/<lang>.json`, add the language to `FILES` in the loader and to `I18N_LANGS`, run `build`.

## Text the server writes
Emails, pushes, reminders and fun facts follow `profiles.language`, which the client keeps
in step with `wr_lang` (and a device with no choice of its own adopts it). See
"Languages — server-written text" in `CLAUDE.md`: fixed text lives in a `strings.ts` beside
each edge function; drips, broadcasts and fun facts are written once in English and
translated automatically (`supabase/functions/_shared/translate.ts`).
