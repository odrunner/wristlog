## The trap worth reading before anyone optimises #13

The natural fix for the 42 MB analytics pull is "filter to `session_summary` rows".
**That would silently break both scripts.** Measured:

```
is_summary=false | 27,689 rows | containing 'psBE=' = 16,713
is_summary=true  |  2,163 rows | containing 'psBE=' =      0
```

`psBE=` is the sole 2.0 detection signature both the rollout tracker and the Sunday
review key on. It appears in **zero** summary rows. A summary-only filter makes both
report **0 users on 2.0** — a wrong answer, not a crash. The fix must be an incremental
cursor over `created_at`, not a row-type filter.
