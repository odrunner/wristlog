## 1. HIGH — SES webhook stamps every open/click/delivery with the *send* time

`supabase/functions/ses-webhook/lib.ts:46`
```js
created_at: mail.timestamp ?? nowIso,
```
`mail.timestamp` is always the time the original message was sent. The real event time is
in `open.timestamp` / `click.timestamp` / `delivery.timestamp` / `bounce.timestamp`.

**Verified in production:**
```
event      created_at (stored)      mail_ts (used)           open_ts (correct)
opened     2026-07-20 00:38:19.604  2026-07-20T00:38:19.604  2026-07-20T00:38:23.684
opened     2026-07-20 00:35:03.291  2026-07-20T00:35:03.291  2026-07-20T00:35:46.337
delivered  2026-07-20 00:38:19.604  2026-07-20T00:38:19.604  (del_ts 00:38:22.746)
```
`sent`, `delivered` and `opened` share an identical `max(created_at)` — impossible if opens
were timed independently.

**Failure:** a recipient opens the Pro V2 broadcast a week after send; the row is written
with the send date. "Recent opens" (`ORDER BY created_at DESC LIMIT 40`) never surfaces it,
and every 24h/7d window mis-attributes it. With the queue draining over many nights, opens
of night-1 emails collapse onto night 1. Send counts and the drain quota are unaffected.

**Fix:**
```js
const evTs = ev.open?.timestamp ?? ev.click?.timestamp ?? ev.delivery?.timestamp
          ?? ev.bounce?.timestamp ?? ev.complaint?.timestamp ?? mail.timestamp;
created_at: evTs ?? nowIso,
```
Existing rows are backfillable from `raw`.

## 2. HIGH — Stats "By Day of Week" ignores the period filter and the measurement rule

`index.html:18963` (call) and `renderDowReport()` body:
```js

```
`renderStats()` passes the filtered `fl` to `renderStatsRow`, `renderWearLeaderboard`,

## 3. HIGH — Year in Review and Monthly Review count measurement shares as wears

`index.html:18461` and `18569`:
```js

const mLogs = logs.filter(l => l.date.startsWith(prefix) && watchIds.has(l.watchId));
```

Both called from `renderStats()` (18966-18967) alongside the `fl`-based cards. They feed
Total Wears, Days Logged, Most Worn, Unworn count, top use case, top day of week — and the
Monthly empty state reads *"No wears logged in …"*.

**Verified:** 5 measurement logs, all with `watch_id`, across 4 users; **4 of 5 are the only
log for that watch on that date**:
```
2026-06-02  masked by a real wear    d70b1a85…
2026-06-13  phantom wear             ae5ff73d…
2026-07-01  phantom wear (x2 rows)   3ec69299…
2026-07-19  phantom wear             f098c7e4…
```

distinct measurement day.

**Fix:** add `isWearEntry(l) &&` to both filters. Leave streaks/badges alone — they
correctly keep counting measurement as engagement.

## 4. MED — Admin open/click rates count raw events → >100% open rates

`sql/2026-07-19-admin-email-engagement-internal-filter.sql:46`
```sql
count(*) FILTER (WHERE event_type = 'opened')  AS opened,
```
`delivered` is one per email; `opened` fires per open (including prefetch and re-opens).
Client divides them at `index.html:14540`.

**Verified:**
```
subject                              delivered  opened  distinct_email_id
"Chrisdd started following you"      2          4       2   → 200%
"⚠️ WRotate weekly-review FAILED…"   1          3       1   → 300%
"New WRotate user: pmmvmi91…"        1          3       1   → 300%
"masont started following you"       3          4       3   → 133%
```
**Fix:** `count(DISTINCT email_id) FILTER (...)` for both. Also makes the metric robust to
the duplicate rows SNS at-least-once delivery can produce (#6).

## 5. MED — Recommendation compares unique wear-days against a raw-row baseline

`index.html:18707-18708`, used at 18809:
```js

const fairShare = totalLogs / watches.length;
const _wWears = wearsForWatch(w.id);              // unique DAYS, excl. measurement
if (rs.prioritizeUnworn && fairShare > 2 && _wWears < fairShare * 0.4) { … }
```
**Verified** — real users log multiple rows per day:
```
user       rows  unique_wear_days
e0af1615…  340   327
9f6fccd3…  338   328
7337041a…  215   200      ← 7.5% inflated baseline
```
Every watch's `neglectedScore` is inflated and the gate flips on for watches actually at

**Fix:** `const totalLogs = watches.reduce((s,w) => s + wearsForWatch(w.id), 0);`

## 6. LOW — `ses-webhook` has no idempotency key; SNS is at-least-once

`ses-webhook/index.ts:125` plain `.insert(row)`. A duplicated `sent` row inflates
`usedToday` in `drainQueue`, shrinking that night's budget. Duplicated `opened` compounds
#4. **Latent, not observed** in current SES data (though 5 Resend-era duplicates exist).
**Fix:** unique index on `(email_id, event_type)` + `ignoreDuplicates`.

## 7. LOW — `loadMyProfile` throws when both inserts fail

the unique-username retry fail, `data` is null and `data.theme_preference` throws. Both
call sites swallow it, so theme/avatar/initials are silently skipped and `myProfile` stays
null. **Fix:** `if (!data) return;` before 7220. The `classifyProfileLoad` guard itself is
correct.

## 8. LOW — Image viewer opens at index 0 after a thumbnail swap

## 9. LOW — One-time brand rebuild can empty the picker for a session

`index.html:13140`. Runs at parse time before any network, persists the wiped list **and**
sets the sentinel unconditionally. If the canonical fetch then fails, `loadUserData`
correctly leaves `brands` alone — so the user keeps only their own brands and the rebuild
never runs again. Self-heals on the next successful load.
**Fix:** set the sentinel inside the success block at 6704.
